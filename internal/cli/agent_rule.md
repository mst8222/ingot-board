# Ingot Board 任务看板

本机有一个 Ingot Board 任务看板，人类在上面给你派发任务、评审你的成果。
通过 MCP 服务 `ingot-agent` 提供的工具与看板交互。

## 何时查看看板

- 每次会话开始时，调用 `list_my_tasks` 查看有没有待执行（todo）的任务。
- 提交完一个看板任务后，再调用一次，继续下一个。
- 用户说"看看看板""领任务""开始干活"之类的话时。

用户在当前会话里给了别的明确指令时，先完成用户的指令，不要擅自切去做看板任务。

## 执行流程

1. `list_my_tasks`：结果按看板顺序排列，第一条最优先。一次只领一个任务。
2. `claim_task`：领取。返回值中的 `feedback` 是人类反馈；其中有驳回（`type` 为 `reject`）时，
   说明上一次提交被打回，本次必须逐条处理驳回意见。
3. 在任务的 `workdir` 中工作，按 `acceptance_criteria` 自行验证。
4. 长任务每 5 分钟左右调用一次 `heartbeat_task` 续租（租约 15 分钟，超时任务会被系统收回）。
   阶段性进展用 `add_task_note` 记录；阶段间隙用 `get_task_feedback` 查看人类是否追加了备注。
5. 完成后调用 `submit_task`，`summary` 写清：改了什么（文件/模块）、怎么验证的（命令与结果）、
   产出物在哪里、还有什么遗留问题。
6. 做不了（缺信息、缺权限、超出范围）时调用 `release_task`，`reason` 写清卡在哪里、需要人类补充什么。
   不要提交半成品。

## 额度

领取前先确认自己还有额度。没有额度时调用 `report_quota`，`quota` 填 `exhausted`，然后 `release_task` 退回，不要开始做。
有额度时可以先 `report_quota` 填 `ok`，再 `claim_task`。

## 约束

- 只处理指派给你的任务，不改动任务范围之外的内容。
- 提交后任务进入人类评审，不要自行宣告任务完成。
